# 停车平台导航重构设计

## 目标

把当前“若依后台 + 停车模块”的菜单观感，调整为“停车场管理系统”的主业务导航。菜单需要体现完整平台骨架，而不是把停车相关页面平铺在一个 `停车管理` 目录下。

## 导航结构

一级菜单调整为：

- 工作台
- 基础档案
- 运营中心
- 客户中心
- 系统管理
- 系统监控
- 系统工具
- 若依官网

其中停车业务不再保留 `停车管理` 目录壳层，直接成为系统主导航。

## 页面归类

### 工作台

- 停车概览

工作台为一级直达菜单，不再显示为“停车管理 / 停车概览”的二级结构。页面仍复用现有 `parking/index` 组件和 `parking:overview:list` 权限。

### 基础档案

- 停车场管理
- 车位管理
- 管理员绑定

基础档案承载场站、资源和人员绑定类配置，强调“主数据/档案”语义。

### 运营中心

- 临停订单
- 月卡订单
- 会员订单
- 支付流水

运营中心承载交易、收费和订单处理相关页面，突出日常运营主线。

### 客户中心

- 用户车辆

客户中心先承接用户车辆页，为后续扩展用户资产、会员档案等页面预留结构。

## 视觉与命名策略

- 一级菜单名称使用平台化分组：`工作台 / 基础档案 / 运营中心 / 客户中心`
- 子菜单保留现有业务页面名称，避免页面标题、权限标识和用户认知同时大幅变化
- 一级菜单图标统一为系统骨架型图标，子菜单保留与当前业务语义匹配的图标
- 一级菜单顺序优先展示停车业务，系统类菜单后置

## 路由与菜单数据策略

- 菜单结构来源仍以 `sql/parking/parking_menu.sql` 为准
- `停车概览` 对应菜单行改为一级直达的 `工作台`
- 原 `停车管理` 目录行迁移为 `基础档案`
- 新增 `运营中心`、`客户中心` 两个一级目录
- 子页面挂载到对应目录下，形成新的动态路由层级
- 概览页内的快捷入口跳转路径同步更新到新层级

## 兼容与约束

- 不改动现有接口权限编码，如 `parking:lot:list`、`parking:payment:list`
- 不改动现有页面组件路径，如 `parking/lot/index`
- 菜单脚本继续保持按业务键幂等更新，不依赖固定 `menu_id`
- 不清理用户已有的非停车菜单，只调整停车业务菜单自身结构

## 测试范围

- 菜单 SQL 测试：验证一级结构、父子归属、业务键和按钮权限挂载是否正确
- 前端冒烟测试：验证概览页中文文案仍存在，快捷入口跳转改为新路由
- 目标结果：停车业务菜单在结构上呈现完整平台骨架，页面跳转与权限不回退
